# hdnews 현행 사이트 명세 (개편 전 기준)

> 기준 시점: 2026-10-13 (`main` 최신 커밋 기준, 코드·설정 파일에서 직접 추출)
> 근거 파일: `index.html`, `assets/app.js`, `assets/issues-core.js`, `assets/style.css`,
> `scripts/collect.py`, `scripts/hsdash.py`, `config/*.json`, `.github/workflows/collect.yml`

---

## 0. 한 줄 요약

GitHub Actions가 **30분마다** 네이버 뉴스 API + 구글뉴스 RSS를 **네이버 65개·구글 57개 검색어**로 긁어와,
**키워드 사전(config/keywords.json) 기반 규칙**으로 회사·탭·유형·리스크를 태깅하고 노이즈를 걸러
정적 JSON으로 커밋 → GitHub Pages의 **순수 JS SPA**가 그 JSON을 읽어 화면을 그린다. 서버·DB 없음.

## 1. 시스템 구성

| 구분 | 내용 |
|---|---|
| 호스팅 | GitHub Pages (`main` 브랜치 루트), 정적 사이트 |
| 수집 실행 | GitHub Actions `Collect news` — cron `*/30 * * * *`(UTC) + 수동 실행. 동시 실행 금지(concurrency) |
| 수집 코드 | `scripts/collect.py` (표준 라이브러리만), `scripts/hsdash.py` (회사 대시보드용 hdhs 연동) |
| 저장 | 저장소에 JSON 커밋 (`chore(data): update news data [skip ci]`) |
| 프런트 | `index.html` + `assets/app.js`(1,426줄) + `assets/issues-core.js`(순수 로직) + `assets/style.css` — 프레임워크 없음 |
| 사용자 상태 | 전부 브라우저 localStorage (로그인 없음) |
| 외부 연동 | hdhs (`https://hdmzp.github.io/hdhs/`) — 홈쇼핑 편성표·hsmoa 랭킹·카드할인·가격추적 |
| 비밀값 | `NAVER_CLIENT_ID`, `NAVER_CLIENT_SECRET` (Actions Secrets) |

### 1-1. 데이터 파일

| 파일 | 내용 | 생성 주기 |
|---|---|---|
| `data/articles.json` | 최근 7일 기사 전체 (현재 14,306건: 네이버 12,732 / 구글 1,574, 노이즈 1,955) | 30분 |
| `data/trending.json` | 급상승 키워드 (유통 전체 `keywords` 20개 + 홈쇼핑 `hsKeywords` 10개) | 30분 |
| `data/briefing.json` | 오늘/7일 집계, 핫이슈 TOP10 id (유통·홈쇼핑) | 30분 |
| `data/issues.json` | 72시간 이슈 묶음 (현재 255개, 상한 600) | 30분 |
| `data/hsdash.json` | 홈쇼핑사별 편성·랭킹·카드할인·가격변동 요약 | 2시간 (실패 시 기존 유지) |
| `data/archive/YYYY-MM.json` | 7일 지난 기사 월별 보관 (현재 196개 파일) | 만료 시 |

### 1-2. 기사 1건의 데이터 필드

| 필드 | 의미 |
|---|---|
| `id` | `originallink`(없으면 `link`)의 SHA1 앞 12자 |
| `title`, `description` | HTML 태그·엔티티 제거, 요약은 200자 컷 |
| `link`, `originallink` | 네이버 링크 / 언론사 원문 링크 (구글은 originallink 없음) |
| `pubDate` | KST ISO8601 |
| `source` | `naver` / `google` |
| `press` | 언론사명 (도메인 매핑, §3-4) |
| `image` | og:image 썸네일 (없으면 빈 문자열) |
| `heat` | 보도량 = 대표 기사 1 + 같은 제목 전재 수 |
| `companies` | 제목+요약에 이름이 나온 홈쇼핑사 (언급 포함) |
| `mainCompanies` | **제목**에 이름이 나온 홈쇼핑사 (주체 기사) |
| `rcompanies` | 제목+요약에 나온 유통사 |
| `tabs` | `retail` / `homeshopping` / `policy` / `ecommerce` / `risk` |
| `categories` | 일반 유형 (홍보·출시 등 11종) |
| `riskCategories`, `riskScore` | 리스크 유형 9종, 점수(가중치 합, 최대 5) |
| `noise` | 노이즈 여부 (true면 대부분 화면에서 숨김) |

### 2-2. 화면(라우트)별 구성

| 화면 | 해시 | 구성 (위→아래) |
|---|---|---|
| **홈** (기본) | `#/home` | ① 📍내 회사 카드(지정 시: 24시간 주요·언급·리스크 수 + 최신 3건) ② ⚡바로가기 아이콘 그리드 12개(N 배지) ③ "어느 회사를 보시나요?" 12개사 원형 카드(인기/주의 배지) ④ 🗞️지금 뜨는 이슈 5개(24시간) |
| **발견** | `#/discover` | 분류 칩(전체/유통/홈쇼핑/정책/e커머스/리스크) → 이슈 칩 6개 → 회사 대시보드 카드 12개(전체·홈쇼핑일 때만) → 급상승 키워드 10개 |
| **이슈 타임라인** | `#/issues` | 전체/팔로우 칩 → 분류 칩 6개 → 이슈 목록(제목·"N개의 기사를 압축했어요"·n분 전·NEW·종 버튼) → 종료된 팔로우 이슈 |
| 이슈 상세 | `#/issue/<id>` | 제목 / 기사 N건·보도 N건·기간·회사·리스크 칩 / 대표 요약 / 팔로우 버튼 / 날짜 구분선이 있는 시간순 기사 타임라인(★스크랩) |
| **유통 NEWS** | `#/retail` | 📈급상승 키워드 12개 → 🔥오늘의 유통 핫이슈 TOP10(카드형) → 🕐최신 기사: 유통사 16개 칩 슬라이서 + 기간 필터 → 기사 피드(최대 300건) |
| **홈쇼핑 NEWS** | `#/homeshopping` | 🔑홈쇼핑 핫이슈 키워드 TOP10 → 🔥오늘의 홈쇼핑 핫이슈 TOP10(한 줄형) → 🏢회사별 최근 기사(7일 막대그래프, 접기 가능) → 📚회사별 기사 모음: 12개사 슬라이서 + 주요/언급 토글 + 유형 필터 → (1개사 선택 시) 회사 대시보드 → 검색·정렬·기간 바 → 기사 피드 |
| 회사 | `#/company/<id>` | 홈쇼핑 NEWS에서 그 회사만 선택한 상태 |
| 회사 목록 | `#/companies` | 12개사 카드 (24시간 주요·언급·리스크) |
| 주제 | `#/topic/<risk·policy·ecommerce·homeshopping·retail>` | 제목 + 기간 필터 + 기사 목록 |
| 리스크 유형 | `#/risk/<리스크 id>` | 제목 + 기간 필터 + 해당 유형 기사 목록 |
| 급상승 | `#/trending` | 유통 전체 20개 + 홈쇼핑 10개 |
| 핫이슈 | `#/hot` | 유통 TOP10(카드) + 홈쇼핑 TOP10(한 줄) |
| 스크랩 | `#/scrap` | ★ 저장 기사 (7일 지나도 유지) |

- 구버전 해시(`#/risk`, `#/policy` 등)는 주제 페이지로, 알 수 없는 해시는 유통 NEWS로 보냄
- 홈·발견·이슈 화면에서 검색어를 입력하면 유통 NEWS로 이동해 결과 표시

## 3. 정보 수집 방식

### 3-1. 수집 소스

| 소스 | 엔드포인트 | 파라미터 | 비고 |
|---|---|---|---|
| 네이버 뉴스 검색 API | `openapi.naver.com/v1/search/news.json` | `display=100`, `sort=date` (쿼리당 최신 100건) | 쿼리 간 0.15초. 키 없으면 건너뜀 |
| 구글뉴스 RSS | `news.google.com/rss/search` | `hl=ko&gl=KR&ceid=KR:ko` | 쿼리 간 0.5초. 제목 끝 " - 언론사" 분리, 원문 링크 없음(리다이렉트) |
| 기사 페이지 (썸네일) | 기사 원문/네이버 링크 | 앞 64KB만 읽어 og:image 추출 | 최근 24시간·이미지 없는 기사 중 (heat+리스크) 상위 **150건/런**, 10병렬, 5초 타임아웃. 구글 링크 제외 |
| hdhs (회사 대시보드) | `hdmzp.github.io/hdhs/` | 편성 `homeshopping/{feed}/{YYYY-MM}.json`, 랭킹 `data/ranking/latest.json`, 카드할인 `homeshopping/promotions/card_discounts.json`, 가격 `pricewatch/current.json` | 2시간 간격 |

- 실패 처리: 요청 1회 재시도(2초 대기) 후 건너뜀. **모든 쿼리 실패 시 기존 데이터 보존하고 종료**.
- 안전장치: 수집 결과가 기존(만료분 제외)의 50% 미만이면 덮어쓰기 중단.
- 네이버 사용량: 쿼리 × 48회/일 (일 한도 25,000)

### 3-3. 수집 파이프라인 순서 (`run()`)

1. 기존 `articles.json` 로드 → 언론사명 백필 → **최신 규칙으로 전체 재태깅** (규칙을 바꾸면 기존 기사에도 적용)
2. 기존 기사 중 정규화 제목 중복 정리 (heat 합산)
3. 네이버 → 구글 순서로 수집 (**제목이 겹치면 네이버 기사가 대표로 채택**)
4. 병합 + 중복 제거 + 신규 기사 태깅 (§4-1)
5. 썸네일 조회 (150건 상한)
6. 7일 보존 → 초과분 월별 아카이브
7. 급상승 키워드 계산 (유통 전체 + 홈쇼핑 전용)
8. 브리핑(집계·핫이슈) 계산
9. 이슈 타임라인 생성 (실패해도 기존 파일 유지)
10. hsdash 생성 (2시간 경과 시, 실패해도 무시)
11. JSON 기록 → Actions가 변경분 커밋·푸시

### 4-1. 중복 제거 (병합 단계)

| 기준 | 처리 |
